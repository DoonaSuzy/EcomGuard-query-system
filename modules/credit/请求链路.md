## 3. 验证码闸门（真正的拦截点）

```js
// scripts/vcode.js:1
var vcodeswitch = 1;   // 1 开启 0 关闭 —— 线上恒为 1
```

```js
// scripts/companysearch.js:34-110  paginationEvent(pageNumber)
if (vcodeswitch == 1) {
  if (getCookie('vcode') == '') {
    updateVocdeFun();
    $('.vcodepop').show();
    $('.mask').show();
    $(".vcodepop .confirm").on('click', function () {
      var txt = $('#vcode').val();
      $.ajax({
        type: "post",
        url: config.VcodeIP + "verify/checkVerify",
        xhrFields: { withCredentials: true },
        async: false,
        data: { verifyInput: txt }
      }).done(function (res) {
        if (res.code == 0) {
          setCookieExpireInOneMinute("vcode", "1");
          $('.vcodepop').hide();
          searchAjax(pageNumber);
        } else {
          updateVocdeFun();
          // 回显 res.msg
        }
      });
    });
  } else {
    searchAjax(pageNumber);
  }
}
```

### Cookie 机制
```js
// scripts/vcode.js:97-102
function setCookieExpireInOneMinute(name, value) {
  var expires = new Date(Date.now() + 5 * 60 * 1000);   // 函数名写"1分钟"，实为 5 分钟
  document.cookie = name + "=" + value + ";" + expires + ";path=/";
}
```
- 非 HttpOnly，仅 `path=/`，host-only `www.creditchina.gov.cn`
- `vcode.js:67-80` `updateVocdeFun()`：先落 `cookienum`（`path=/;domain=.creditchina.gov.cn`，1 天），再
  `$('#vcodeimg').attr('src', config.VcodeIP + 'verify/getVerify?_v=' + Math.random())`
- `vcode.js:35-37`：`beforeunload` 时清除 `cookienum`
- `vcode.js:104-155` 的 `validateCaptcha` / `validateHuman` **整段被注释**，不生效

### 验证码图片
```
GET https://public.creditchina.gov.cn/private-api/verify/getVerify?_v=<random>
→ 200, content-type: image/jpeg, 95 × 25 px, 约 1.7–2.6 KB
```
- **内容是 4 位数字+字母（大小写混合）**，不是汉字
  - 实证：`logs\credit_check.log` 里实际通过服务端校验的样本是 `code=ptva`、更早的 `code=fP5`（3 位，被 4 位长度校验丢弃后换图）。
    汉字不可能被提交成拉丁字母还通过校验，故此处早期记录有误
- 校验接口：`POST /private-api/verify/checkVerify`，`application/x-www-form-urlencoded`，`verifyInput=<4字符>`
  - 成功 `{"code":0}`
  - 失败 `{"msg":"验证码已失效，请重新申请验证码","code":-1}`

## 4. 实测状态码

| 场景 | 结果 |
|---|---|
| 首次访问页面 | `412` → 加载 `/z9ItHZeV1nhb/*.d07207d.js` → 通过（瑞数两跳） |
| 同批 `GET /private-api/info` | `200`（证明瑞数签名有效，412 不是卡点） |
| 带 keyword 进结果页自动发 `catalogSearchHome` | `400` |
| 页面内 fetch 同一明文 URL（带 credentials） | `400`，body `{"status":10001,"message":"验证码已失效，请重新申请验证码！","data":null}` |
| 手动 `document.cookie="vcode=1;path=/"` 后搜索 | 客户端放行，**服务端仍 400** |
| `POST checkVerify` 传 `verifyInput=test`（未先取码） | `200`，`{"msg":"验证码已失效，请重新申请验证码","code":-1}` |

**结论**：`vcode` cookie 只是客户端 UI 同步；服务端另有一份会话级验证码状态，必须先取码、再提交正确值，之后 5 分钟内搜索才放行。

## 5. 自动化可行路线

| 方案 | 做法 | 代价 | 状态 |
|---|---|---|---|
| **D（已落地）** | ddddocr 本地识别 + 换图重试，全自动 | 无需 key；单张约五成，12 次重试内必过 | ✅ 已实现并实测（`credit_check.py`） |
| A | 人工过一次验证码 → 5 分钟内批量跑完名单 | 每 5 分钟需人工读 4 字符 | 备选（无 OCR 依赖时） |

| C | 找不走 vcode 的只读路由 | 尚未发现 | 未实现 |

### 取验证码到本地供人眼的可行做法
- `fetch` + `blob()` + `FileReader.readAsDataURL` → **间歇性** `NetworkError`（OpaqueResponseBlocking）
- `fetch` + `arrayBuffer()` → 被 Xray 拦截：`Accessing TypedArray data over Xrays is slow, and forbidden`
- `canvas.drawImage(img)` + `toDataURL()` → **跨域污染，`The operation is insecure.`**
- **可行**：把 `#vcodeimg` 用 CSS 放大（`width:760px; image-rendering:pixelated`）后，由 Playwright 元素截图 / 或直接用有头浏览器让人看

## 6. 抓包排障备忘
- `network_capture` 需显式 `action=start` 且 `capture_body=true` 才存 body
- `navigate(clear_network_capture=true)` 会清历史
- `remove_hooks` 会同时清掉 `init_scripts` / `persistent_scripts`，排障前先确认没被自己干扰
- `window.selfObj` / `window.jQuery` / `window.vcodeswitch` / `window.config` 在 `evaluate_js` 全局作用域里都是 `undefined`，但 `search_code` 能在已加载脚本里搜到它们 —— **变量不可见 ≠ 脚本没跑**
