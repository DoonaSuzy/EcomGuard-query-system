### 2.2 形态 A 的两个硬缺陷（实测）

```
lifespan 执行顺序: ['ROOT START', 'ROOT STOP']     ← 子应用的 SUB START/SUB STOP 从未出现
GET /mod/probe → {"store":"MISSING"}                ← 子应用 app.state 未被赋值
root.openapi()["paths"] → []                        ← 主应用不合并子应用 paths
```

修复方式（实测有效，但仍是弯路）：主应用 lifespan 里 `async with sub.router.lifespan_context(sub): yield` → 顺序变为 `['ROOT START', 'SUB START', 'SUB STOP', 'ROOT STOP']`。

但 openapi 为空这条无法绕过——前端就无法用 `openapi-typescript` 一次生成全部类型。**因此不选形态 A。**

## 4. 前端子路径托管的三个硬性前提

这三条漏一条就白屏或 404，全部实测。

### 4.1 两套产物都必须带 base 重建

| 项目 | 现状 base | 子路径下表现 |
|---|---|---|
| WIPO `web/vite.config.js:16` | `base: './'`（相对） | `/wipo/` 正常，`/wipo/input/detail` 下资源请求变成 `/wipo/input/assets/...` → 404 |
| credit `frontend/vite.config.ts` | 无（默认 `/`，绝对） | `/credit/` 下请求 `/assets/index-*.js` → **404，整站白屏**（`#app.children`==0） |

重建命令（实测成功）：

```powershell
cd F:\projects\GO1\python_ver\web
npx vite build --base=/wipo/ --outDir <目标目录>

cd F:\projects\GO1\reverse-records\frontend
npm run build -- --base=/credit/ --outDir <目标目录>
```

重建后 `index.html` 引用变为 `/wipo/assets/index-*.js` / `/credit/assets/index-*.js`。

**关键实测：动态 chunk 也能正常加载。** credit 是路由分包（15 个 assets 文件），主 chunk 里 Vite 生成的是 `__vite__mapDeps` 数组，内容是**相对** `"assets/OverviewView-*.js"`，不含 `/credit/assets` 前缀。看起来像会 404，但实测：

| 请求 | 结果 |
|---|---|
| `/credit/assets/index-DfzIpmNB.js` | 200 |
| `/credit/assets/OverviewView-PZF0daxO.js` | 200 |
| `/credit/assets/EmptyState-CFMeUydf.js` | 200 |
| `/credit/assets/NotFoundView-DYt6fw7h.js` | 200 |
| 浏览器访问 `/credit/`、`/credit/jobs`、`/credit/jobs/abc`、`/credit/submit` | `#app > *` children=**2**，无静态资源 4xx |

原因：Vite 的 `__vite__mapDeps` 用 `import.meta.url` 做基准解析，而入口脚本是从 `/credit/assets/index-*.js` 加载的，所以相对 `assets/...` 会解析到 `/credit/assets/...`。**只要 index.html 里的入口引用是绝对路径（`--base` 保证了这点），动态 chunk 就自然正确。**

> 早期探针曾观察到 `/credit/jobs` 下 `404 /assets/OverviewView-*.js`，那是**用未带 base 的旧产物**测的（入口引用 `/assets/index-*.js`，被解析到根）。用 `--base=/credit/` 重建后不再复现。

> 长期做法：把 base 写进 `vite.config`，用环境变量控制（`base: process.env.VITE_BASE || '/'`），避免每次构建都要带参数。

### 4.2 credit 的 18 处路由字面量**不用改**

`frontend/src/router/index.ts:14` 是 `createWebHistory(import.meta.env.BASE_URL)`。用 `--base=/credit/` 构建时，`import.meta.env.BASE_URL` 自动变成 `/credit/`：

- 产物里 `"/credit/"` 出现 2 次
- `router.push('/submit')` 等 8 处相对 push 全部被 base 兜住
- `<router-link :to="n.to">`（`frontend/src/App.vue:45`，`NAV` 在 `:17-21`）渲染出 `/credit/overview` 等绝对 href

**这是 vue-router 的标准行为，不需要逐个改字面量。**

### 4.3 挂载顺序与重定向

```python
# 顺序不能错
root.include_router(build_api_router())      # 1. API 先注册
root.include_router(credit_api.router)       # 2. credit API

root.get("/credit")(lambda: RedirectResponse("/credit/", 307))   # 3. 显式重定向（必须）
root.mount("/credit", SPA(credit_dist))      # 4. credit 静态
root.mount("/wipo", SPA(wipo_dist))          # 5. wipo 静态（拓扑 A）
```

- **重定向不能省**：`mount("/credit", ...)` 后 `GET /credit`（无尾斜杠）会被其他兜底接走，返回错误页面。实测补 307 后 `/credit` → `/credit/` 正确。
- **挂载顺序**：静态 mount 必须放在 API router 之后，否则 `/api/*` 会被静态目录抢走。

`SPA` 类实现（子路径 SPA 兜底，实测有效）：

```python
class SPA(StaticFiles):
    def __init__(self, directory, **kw):
        super().__init__(directory=directory, html=True, **kw)

    async def get_response(self, path, scope):
        try:
            return await super().get_response(path, scope)
        except StarletteHTTPException as e:
            if e.status_code == 404:
                return FileResponse(str(Path(self.directory) / "index.html"))
            raise
```

## 5. 数据库：分库 vs 分表

### 5.1 表名零冲突（分表的前提）

| 项目 | 表 |
|---|---|
| WIPO | `trademarks`、`reports`、`check_runs` |
| 营业执照 | `jobs`、`results` |
| 同名表 | **0** |

### 5.2 分库实测（推荐）

真 MySQL 8.4.9（端口 3307）建两个库：

| 库 | 表 | 来源 |
|---|---|---|
| `wipo_trademark` | `check_runs`、`reports`、`trademarks` | `python cli.py db-init` 自动建 |
| `credit_check` | `jobs`、`results` | 手写 DDL 建（utf8mb4 / InnoDB / 外键级联） |

**端到端验证**：合并应用 + 双库，`POST /api/trademarks` 200 写入成功、`POST /api/jobs` 202 返回 job_id；回查 `wipo_trademark.trademarks` 有数据、`credit_check.jobs` 有记录。浏览器两模块 4xx=0。

### 5.3 分表实测（同库不同表，也成立）

把 `jobs`/`results` 建进 `wipo_trademark` 库 → `SHOW TABLES` = 5 张（`check_runs`/`jobs`/`reports`/`results`/`trademarks`），整链路重跑通过，`ix_jobs_created` 索引建成功。

**技术上零成本，但不推荐**：备份粒度、权限隔离、未来拆库都要返工。

### 5.4 credit 上 MySQL 的改造量（实测，很小）

`api.py:185-303` 的 `Store` 类只有 **11 个方法、16 条 SQL**：

| 改造项 | 数量 | 说明 |
|---|---|---|
| `?` 占位符 → `%s` | **29 处** | pymysql 要求；分布在 14 条 SQL 里（`api.py:211` 5 个、`:218`/`:221`/`:224`/`:227`/`:230`/`:234`/`:238`/`:254`/`:258`/`:264`/`:271`/`:278` 各 1 个、`:245` 12 个） |
| 删 `PRAGMA` | **2 处** | `api.py:199 journal_mode=WAL`、`:200 foreign_keys=ON`（SQLite 特有） |
| `INSERT OR REPLACE` → `ON DUPLICATE KEY UPDATE` | **1 处** | `api.py:243` |
| 连接方式 | 1 处 | `sqlite3.connect` → `pymysql.connect(..., cursorclass=DictCursor)` |
| `AUTOINCREMENT` / `datetime(` | **0 处** | 无需处理 |

实测移植后全通过：`create_job` → `set_state` → `add_result`×2 → `set_state(done)`；`list_jobs`/`get_results`/`counts` 正确；**幂等重放** `add_result` 后 `counts` 正确变化；`JSON_TYPE(request)`='OBJECT'、`JSON_UNQUOTE(JSON_EXTRACT(request,'$.min_delay'))`='3.5'；`results JOIN jobs` 可用。

### 5.5 数据库选型建议

| 场景 | 建议 |
|---|---|
| 现在（数据量 8 行 / 4 行） | 分库，但都可以先留在 SQLite（`data/jobs.db` 与 `data/e2e.db`） |
| 要统一运维 | **同实例双库**（`wipo_trademark` + `credit_check`），本方案默认 |

## 6. 运行时依赖：能否共用一个 venv

此前结论「playwright 1.62.0 vs 1.61.0 硬冲突，两后端不能共 venv」**需要修正**：那只对测试依赖成立。

### 6.1 实测：共 venv 可行

新建干净 venv，先装 `fastapi==0.143.0 uvicorn==0.54.0 camoufox==0.4.11 ddddocr==1.6.1`，再叠 WIPO 的 `requirements.txt`，最终版本：

```
sqlalchemy 2.1.4 / aiomysql 0.3.2

structlog 26.1.0 / alembic 1.20.0
pytest 9.1.1 / ruff 0.17.0 / httpx 0.28.1
```

关键事实：
- `camoufox` 对 playwright 的依赖是**无版本上限的裸依赖**（`importlib.metadata.requires("camoufox")` 输出 `'playwright'` 裸名）→ 1.62.0 能覆盖
- `from camoufox.sync_api import Camoufox` OK，`camoufox.pkgman.installed_verstr()` = `135.0.1-beta.24`
- credit 回归在此 venv 里 **189 passed**（与项目 `.venv` 一致）

### 6.2 三个必须处理的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| WIPO 缺 `aiosqlite` 声明 | `requirements.txt`/`pyproject.toml` 都没声明，但 `tests/conftest.py:71` 与 `verify_*.py` 全部覆盖成 `sqlite+aiosqlite:///` → 裸装 25 failed / 12 errors | 补 `aiosqlite==0.22.1`（实测后 43 passed / 68 断言 / 63 断言全绿） |
| WIPO E2E 需另装浏览器 | 首次 `pytest tests` → 33 passed / 77 errors | `$env:PLAYWRIGHT_DOWNLOAD_HOST='https://npmmirror.com/mirrors/playwright'` + `python -m playwright install chromium` |
| credit 回归不能跑系统 Python | 系统 Python 下 **5 failed**（`healthcheck` 报「当前不在 venv 内」「缺少依赖 camoufox」） | 必须用项目 venv 或上述共用 venv（这是健康检查的**设计**，不是缺陷） |

### 6.3 credit 必须单进程单 worker

`api.py:331-364` 的 `Worker`：
- `submit()` 把 job_id 塞进内存队列 `self.q` + `cv.notify()`
- `_run()` 单线程 `while True` 串行消费
- `_ensure_checker()` 懒建**单个** Camoufox 实例

→ 内存队列与浏览器实例都不跨进程。**多进程部署会破坏作业串行语义。**

WIPO 侧同样有 `--workers 1` 约束（`README.md:426-430`：`check_runs` 是单行状态机，多进程下状态会错乱）。

**两个模块的约束恰好一致，所以合并成单进程是自然选择，不是妥协。**
